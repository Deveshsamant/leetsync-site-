What it does

Everything happens on submit

You solve on LeetCode as usual. The moment a submission is accepted, LeetSync does the rest.

01
01 On submit

Automatic pushes

Accepted solutions land in your repo in seconds, filed by problem number, with the language extension you actually used. Re-submitting adds sol2 rather than overwriting your first attempt.

02
02 Per push

A README that writes itself

Difficulty badges against LeetCode's real totals, a rolling-year solve calendar, language mix, and an index that collapses into per-difficulty sections once it outgrows a flat table.

03
03 895 problems

Seven study sheets

Seven sheets covering 895 distinct problems, matched by number so one 250 — 895 problems after de-duplication. Solving one ticks it everywhere it appears.

04
04 Every verdict

Knows what you struggled with

Every verdict is recorded, not just the accepted one. Filter for problems that took several attempts, or ones you have not revisited in a month, and see which topics you are weakest at.

05
05 Daily habit

Streaks and achievements

A solve calendar, a current and best streak, and achievements that unlock as you go. Enough to keep the habit without turning practice into a slot machine.

06
06 Retry queue

Survives a bad connection

Pushes that fail are queued and retried, not lost. Auth problems and rate limits are recovered the same way, and the popup tells you what is waiting.

07
07 Two computers

One streak, either machine

Sign in on a laptop and a desktop with the same token and repo and they converge on their own. Progress merges through the repository rather than a server — solved problems, sheet ticks and achievements are unioned, so nothing is lost whichever machine syncs first, and Monday here plus Tuesday there is a streak of two.

08
08 Battle

A public leaderboard

All time, this week and today, top ten in each, with your own position pinned underneath. Hard 10, Medium 5, Easy 3, counted once per problem. You are on it only while you have usage reporting turned on, under the username you chose.

09
09 Both directions

Say something, hear back

Feedback, an issue or a suggestion, sent from Settings with your version attached. The answer arrives inside the extension — a message that quotes what you wrote, shown once. The same channel carries the occasional announcement, and every one of them is dismissible.

      How it works

      From accepted to committed

      Three moves, none of them yours. Keep scrolling to follow one solve all the way into the repository.

      01
      Trigger · Step 01

      You hit Submit

      LeetCode returns Accepted. That verdict is the only trigger — nothing polls, nothing scrapes, nothing runs while you are still typing.

      02
      Package · Step 02

      LeetSync packages the solve

      The code with the right extension, runtime and memory, your notes and the problem's own page — filed under the problem number, queued if the network is not there.

      03
      Commit · Step 03

      Your repo updates itself

      One commit, one scope — Contents: write. The index, the difficulty badges and the solve calendar are rewritten to match.

      Every screen

      Seven screens, explained

      Pick a screen. Each one is a real capture of the extension running — top to bottom, in whichever theme the page is wearing — beside what every part of it does and how it decides what to show.

      First run · steps 1–3

      Connect once, in about a minute

      The wizard runs until a token and a repository are both saved, and nothing else in the extension is reachable before that. Five steps, and the step you reached is remembered — closing the popup half way through picks up where you left it, not back at the start.

      • 01
        A token, not an OAuth app A fine-grained GitHub token scoped to one repository with Contents: Read and write is the whole permission surface. It is kept in Chrome storage and sent to api.github.com and nowhere else — LeetSync has no server that could receive it.
      • 02
        A username, checked while you are still here Three to twenty-four characters, and unique across LeetSync users. Checking that sends the name on its own and nothing with it. The name is claimed by the background worker rather than the popup, because a popup is destroyed the instant it closes and would take the request with it.
      • 03
        The repository can find itself Set up automatically from my token looks for leetcode-solutions on your account and creates it if there is none. You can also type owner/repo, or have a new one made private — creating a repository is the one thing a fine-grained token cannot do, so that path asks for a classic repo token.
      • 04
        Nothing is pushed until it works The last step verifies the token against the repository before it declares setup finished, so a typo surfaces here rather than as a solve that silently never arrives.
      First run · step 4

      The data question, asked before it matters

      Setup is already complete by the time this appears, which is the point: neither switch changes whether your solutions sync. It is asked here so the answer is yours rather than a default you never saw.

      • 01
        Share usage data — off, and it stays off Turn it on and LeetSync sends your username, the extension version, your theme, your README theme, which study sheets you use and how far through them you are, and every submission result: problem, difficulty, language, verdict, runtime and memory. It does not record which tab you opened, or that you opened the popup at all.
      • 02
        Count me as an active user — on, and much smaller A random ID and the version number, at most twice a day. That is the whole of it, and it is all that leaves your browser while the switch above is off. It exists so an install still in use can be told apart from one that was abandoned. Switch this off too and nothing is sent, ever.
      • 03
        The leaderboard rides on the first switch Sharing usage data is also what puts your username and score on the public leaderboard in Battle. Turning it back off takes you off the board and deletes the queue that had not been sent yet.
      • 04
        Never, under either switch Your GitHub token, your repository, your GitHub username, or your solution code. Sharing code is a third switch, in Settings, off even when reporting is on.
      Tab 1 of 5

      Whether it is working, answered at a glance

      The tab the popup opens on, built around one question: did the last solve actually land. Everything under that is the shape of the work — what you have done, when, and how hard it was.

      • 01
        Sync status and the repository line Connected, syncing or failed, with the time of the last push beneath it. The row under that links straight to the repo and branch the pushes are going to, so “is it really in GitHub” is one click rather than an assumption.
      • 02
        Health — the last six days Six bars, one per day, filled if you solved anything. Deliberately short: a streak counter tells you about a run, this tells you about the week you are actually in.
      • 03
        Solved, pushes and the streak Solved counts distinct problems; pushes counts commits, which is the larger number because re-solving in another language is another file. The streak carries your best alongside the current one.
      • 04
        Difficulty and ninety days of activity One stacked bar for the Easy / Medium / Hard split, and a heatmap of the last ninety days in four intensities. Both are drawn from the record on your own machine, so they are right whether or not reporting is on.
      • 05
        Fifteen achievements Unlocked from what you have already done — first push, ten solved, a week-long streak, a solve after midnight, three languages. They are stored with your progress, so they survive a reinstall.
      • 06
        Topics to work on Appears only once there is something to say. LeetSync keeps an attempt count per problem, ranks the topics that took you the most tries, and lists them — the closest thing to a revision list that does not need you to keep one.
      • 07
        Contest solutions, held back A solve made during a live contest is queued rather than pushed, so a public repository cannot leak your approach while the contest is still running. The card says how many are waiting and pushes them on your word.
      • 08
        The offline queue Lose the network and pushes stack up locally behind a banner saying how many. They go out when the connection returns, in order, without a duplicate.
      Tab 2 of 5

      Everything you have solved, and what to revisit

      Every problem LeetSync has pushed, newest first, with the language and how many solutions exist for it. Two of the six filters are the reason this tab is more than a list.

      • 01
        Search by title or number Types straight through the list — 146 and lru both find LRU Cache.
      • 02
        Struggled — more than one attempt LeetSync counts attempts per problem as you submit, so this is the set you did not get first time. Sorted hardest-won first, which makes it a revision queue rather than a filter.
      • 03
        Stale — solved over thirty days ago Oldest first. The two answer different questions: struggled is what was hard, stale is what has had time to fade.
      • 04
        Expand to read what you wrote Each row opens to the solutions stored for that problem, one per language, fetched from your repository rather than kept a second time locally.
      • 05
        Delete, with a confirm Removes the problem and its files. The button asks twice, because the first tap is one pixel from the expand arrow.
      Tab 3 of 5

      Seven study sheets, ticking themselves

      Seven sheets — 1,667 rows over 895 distinct problems, shipped inside the extension rather than fetched, so they work offline and cannot change under you. Each keeps its author’s own sections, and links back to the original.

      • 01
        Progress that fills in as you solve A solved problem is matched to every sheet it appears in by problem number, so one solve can advance four sheets at once. Nothing to tick by hand unless you want to.
      • 02
        Tick by hand as well For problems you solved before installing LeetSync, or solved somewhere else. Manual ticks and automatic ones are stored the same way and merge the same way across computers.
      • 03
        Sections, not one long list Each sheet keeps its author’s own structure — “Learn the basics”, “Binary search” — with a per-section count, so progress reads as a curriculum rather than a percentage.
      • 04
        The full tracker is one click away Show more opens the whole thing as a page: all 895 problems, search, filter by sheet or difficulty, and every sheet at once.
      Tab 4 of 5

      A public board, and rivals you pick yourself

      Two different kinds of competition in one tab. The leaderboard is every LeetSync user who opted in; rivals are people you added by GitHub username, and need nothing from them at all.

      • 01
        The leaderboard — all time, this week, today Top ten in each range, with your own position pinned underneath whether or not you made the ten. It reads the same submission records usage reporting sends, so it is live rather than a snapshot.
      • 02
        Hard 10, Medium 5, Easy 3 Counted once per problem, so re-solving something in a second language does not score twice. The weekly and daily boards count only problems first solved inside those windows.
      • 03
        You are on it only if you opted in Sharing usage data is what puts you on the board. The name shown is the username you chose; clear it and you appear as Anonymous. Turn reporting off and you come off the board entirely.
      • 04
        Rivals, from public repositories Add someone by GitHub username and LeetSync finds their solutions repo, or name the repo yourself. It reads what is already public: the commit history of their solutions folder. They need no extension, no account, and no say in it.
      • 05
        The weekly challenge You against your rivals on problems solved since Monday, reset weekly, with the days remaining in the header.
      Tab 5 of 5

      Every switch, on one screen

      The longest screen in the extension, deliberately — nothing here is buried behind an advanced link. It is grouped rather than paginated: GitHub, appearance, reporting, your data, feedback, devices, about.

      • 01
        GitHub — and a way to check it Token and repository, with Verify connection to prove the pair works before you rely on it, and Restore from GitHub to rebuild the local record by reading what is already in the repo.
      • 02
        Two themes, and a third for the README Signal — near-black with green — and Modernist, light with a red accent. The stat panel LeetSync writes into your README has its own light/dark setting, because the repo is read by people who never see the popup.
      • 03
        Usage reporting, in full The two switches from setup, a third for sharing solution code that stays off even when reporting is on, the username the leaderboard shows, and your install ID in plain sight so you know the ID that identifies you.
      • 04
        Your data, as a file Export writes solved problems, streak, achievements and sheet ticks to JSON; import reads one back. The token is never in the export — that belongs in GitHub, not in a file in your downloads.
      • 05
        Say something, and hear back Feedback, an issue or a suggestion, sent to the developer with your username, install ID and version — a bug report without a version is not much use. The reply comes back inside the extension, as a message quoting what you wrote, shown once and then gone.
      • 06
        Devices — and signing out When your progress last merged, a Sync now, and a sign-out that publishes your progress before it clears this computer’s copy along with the token. Sign back in with the same token and repo and all of it returns.

      Privacy

      Off by default, and it means it

      Three switches, each one listed here in full rather than summarised. The default state is the one you get by doing nothing, and by doing nothing you share almost nothing.

      Local only

      Stays on your device

      • ·Your GitHub token, in Chrome storage
      • ·Your repository name and branch
      • ·Solved problems, streaks, achievements
      • ·Sheet progress, attempt counts and notes
      • ·Which tab you opened, and that you opened it at all
      Opt in

      Sent only if you opt in

      • ·A random install ID, or the username you chose
      • ·The extension version, your theme and README theme
      • ·Which study sheets you use and how far through them you are
      • ·Every submission result — problem, difficulty, language, verdict, runtime, memory
      • ·Your username and score, on the public leaderboard
      • ·Solution code — a separate switch, off even when reporting is on
      Never

      Never collected

      • ·Your token, repo name or GitHub username
      • ·Your IP address — there is no column for it
      • ·Error text, which can contain repo paths
      • ·Browsing history or any ad identifier
      • ·Anything at all, with both switches off

      There is a third setting, on by default and much smaller than the other two: count me as an active user sends a random ID and the version number at most twice a day, so an install still in use can be told apart from one that was abandoned. No problem, no verdict, no theme. Switch that off as well and nothing leaves your browser.

      Turning reporting off deletes the queue, stops the sending and takes you off the leaderboard. Feedback you send from Settings is separate again and works either way — it carries your username, install ID and version, and nothing else. Read the full policy →
